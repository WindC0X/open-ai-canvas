# 画布浮动控件设计沉淀：顶部操作区与底部 Dock

> 范围：无限画布的顶部项目操作区、底部画布工具 Dock、小地图，以及工作模式切换。
> 目标：让画布操作控件形成统一的浮动面板系统，并在不同主题和视口下保持稳定对齐。
> 状态：已实现首版，构建与当前画布回归已确认。

## 1. 设计方向

画布本身是创作空间，操作控件不应占用固定内容栏，也不应把按钮散落在画布节点之间。因此控件采用独立浮动面板：

- 左上放置项目菜单、画布名称和重命名入口。
- 右上放置搜索、导入、性能、积分、专注、分享和 Agent 等操作。
- 左下保留画布视图控制和素材空间 Dock。
- 工作模式切换放在右下，与左下 Dock 共用底部安全区，避免顶部中央出现额外的孤立控件。

## 2. 视觉合同

顶部操作区和底部 `FloatingDock`（浮动 Dock）复用 `canvasDockStyle`（画布 Dock 样式合同）：

- `--dock-surface`：浮动面板表面。
- `--dock-border`：主题边界。
- `--elevation-overlay`：面板层级阴影。
- `--dock-command-hover`：控件悬停表面。
- `--dock-command-active`：持续激活状态表面。

普通操作按钮默认透明，只有悬停或持续激活时才显示控件表面；面板本身负责边界和阴影，避免每个按钮都形成独立卡片。

## 3. 工作模式切换

`CanvasWorkspaceModeSwitch`（画布工作模式切换）是右下角独立浮动面板，不再挂在顶部栏中间：

- 触发器与底部 Dock 使用同一高度、圆角、边界和阴影。
- 菜单从触发器上方展开，并与右侧边缘对齐，避免遮挡底部工具栏和画布主体。
- 外层定位使用 `--canvas-inset-x` / `--canvas-inset-y`，与左下视图控制保持同一水平基线。
- 简洁模式和专业模式继续使用原有 `workspaceMode` 状态，不改变节点渲染和生成逻辑。

- `web/src/pages/canvas/canvas-project-top-bar.tsx`：顶部左右浮动面板，以及工作模式切换组件和下拉菜单。
- `web/src/pages/canvas/project.tsx`：将工作模式切换定位到画布右下角，并与底部控制使用同一安全区。
- `web/src/components/canvas/canvas-zoom-controls.tsx`：底部视图控制 Dock 的既有实现，作为浮动控件视觉基准。

## 5. 小地图信息表达

小地图是“定位与导航”视图，不复制完整节点内容，但必须让节点在缩略比例下仍然可识别：

- 图片节点优先复用 `storageKey`、预览地址或导入源生成缩略图；资源通过缓存组件延迟加载。
- 所有节点保留一个短标题标注。标题单行显示并限制最大宽度，过长时省略，悬停可查看完整名称。
- 非图片节点继续使用类型色块；图片缩略图加载失败时回退到类型色块，不伪造媒体内容。
- 可加载缩略图的图片节点不超过 24 个时显示缩略图；超过阈值后统一回退到色块，避免小地图成为媒体解码热点。
- 标注只覆盖在小地图上，不移动画布节点，也不做空间避让；折叠背板内的节点不重复显示。

底部“适应画布”命令的语义是把当前画布内容整体纳入视口，和小地图的导航职责分开：小地图用于定位，适应画布用于一次性恢复内容总览。

## 6. 响应式与交互边界

- 桌面端顶部左右面板保持同一顶部安全区；底部左右面板保持同一底部安全区。
- 窄视口沿用 `--canvas-inset-y + --space-16` 的底部避让规则，避免与移动端底部工具区域重叠。
- 工作模式菜单打开时支持点击外部区域和 `Escape` 关闭。
- `prefers-reduced-motion` 下关闭或缩短面板和选项的进入动画。
- 本次只调整控件位置和视觉层级，不改变菜单命令、模式持久化和画布操作行为。

### B4 徽标四档

`lib/feature-badges.ts` 承载四档徽标：`new` / `experimental` / `legacy` / `member`。落点约束：

- **扩展现有字段**：`AddNodeMenuCommand.badge?: string`（tool-definition.ts:218）已存在，新徽标类型并入该字段语义，不另起注册表；

- `member` 档与未来 R11 订阅权益联动，当前只预留类型不实现权益判定。

### B7 功能门控三态

在既有 `RequireFeature` 之上引入三态语义：`allowed | locked | hidden`：

- **allowed**：正常可用；**locked**：可见但禁用+解锁指引（升级/开启开关）；**hidden**：完全不可见（按用户群/配置）；
- **「隐藏」和「禁用」是两种沟通方式**——锁定面必须保留入口并说明解锁路径，隐藏面不产生任何视觉痕迹；误用 locked 表达 hidden（或反之）按词汇混用处理；
- 与能力组织层毕业机制同批实现：新手引导态露 6 动作（其余 hidden），解锁后 allowed（Magnific 6+46 渐进披露范式、TapNow 门控画布同源）。

### B8 快捷键教学层（[d]）

`canvas-shortcuts-modal.tsx` 已存在，但只在右键菜单可达且只显示 ⌘Z/⌘V 两个示例——补「教学入口」：

- `?` 帮助菜单四件套（教学综述第一梯队件 3）中的「快捷键」项直接挂此 Modal，入口从右键菜单扩为常驻；
- Modal 内容从 shortcuts 注册表全量生成（复用现有注册表数据，不手抄清单）；
