## 三、Auto-3 设计（Jev 层，v2 重写）

### 3.1 三层结构

```
任务（prompt/节点/场景）
 ↓ 第 0 层 规则底座（确定性，永远在，可独立出结果）
 ↓ 第 1 层 Jev 顾问（可选，不依赖）
    state = 底座候选 + prompt 摘要 + 用户偏好摘要
    questions = 模型适配 Score（score-then-rank）+ 认怂 Noul
    超时/失败/未配置 → 静默回落第 0 层，生成零阻塞
 ↓ 第 2 层 偏好反哺（采集先行；闭环后置，见 §五）
```

### 3.2 原语映射（修订）

| 原语 | v2 映射 | 修订说明 |
|---|---|---|
| Score | 任务适配度（逐模型独立打分后排名） | **score-then-rank 取代 14 路 Choice**：候选集增删时校准/偏好/滞回不失效；Choice 仅限「规则候选 top-k」这类有限固定菜单 |
| Noul | **预选认怂门**（三场景：能力硬断崖 / 意图熵极大-top1与top3差<5% / 成本越级>10倍） | UX = 橙色 [? 待确认] + 自动展开选择器 + 锁定高亮 2 个最近候选「二选一」，不是报错弹窗 |
| ~~Score(价格/稳定)~~ | **删除**——效用 λ 是产品政策旋钮，不外包给 Jev | 参数不可识别问题 |

联合一致性约束：三原语结果可矛盾（选 A 但 A 分低），合批省钱不构成理由——Noul 只在（再校准后的）适配分置信低于门时启用。

### 3.3 时序与竞态（修订）

- **预选只出建议 Badge，不改 Model ID**；生效卡点 = 节点失焦/提交（防参数面板闪烁雪崩）
- 提交必须快照决策；迟到预选只作用于下一次生成
- **手选粘滞**：防抖窗口内手动切模型 → 迟到预选不得覆盖，且覆盖尝试计负投票
- 复制节点不计「反复手选」信号；retry/regenerate 沿用已记录决策走 route_attempts（不重新预选——防把模型质量遥测与 auto 质量遥测搅在一起）
- 多节点并发：偏好 store 读改写竞态防护；同 prompt 兄弟节点缓存共享策略随粒度裁决定
- 预选端点：新增服务端 API（鉴权/限流/prompt 摘要长度上限）；跳过率当 SLO 埋点（官方 70-500ms 无 p99 口径，超时预算需实测定）

### 3.4 校准与统计（修订，取代 v1 4.4 的矛盾设计）

- **raw 概率分布必须留档**：温度0+缓存仅用于执行路径的确定性；统计与置信门只用 raw p（温度0=销毁校准，缓存=样本不独立）
- **再校准前置**：时间切分（禁随机切，偏好有漂移）→ Platt/isotonic 按题型分开 → 可靠性图 + ECE/Brier；未再校准的 raw 分只进附录
- **「置信可用」操作定义**：分箱后经验频率≈报告概率，且 decision-curve net benefit 优于「永远规则」「永远 Jev」两条参考线
- 样本量：高置信段优于规则 δ=5pp ≈ 1500 独立决策（用户/节点级聚类，有效 n ≪ log 行数）；不足则延长 shadow，不许降标准
- 三套门（Score/Noul/各题型）独立预登记，**shadow 阈值不可迁移到 advisory**（jaggedness 的阶段维度版）
- 分层统计：场景 / 新老用户 / 候选集大小 / 是否 Featured / 网络条件——总体指标被简单题稀释，Jev 价值只可能在难例
- negative result 也预登记：再校准后高分段仍无 uplift → 置信分只当日志，永不进路由

### 3.5 硬约束（jev-router 尸检移植 + 审查扩充，六条）

1. shadow 先行（且 shadow 数据服务端落库，含规则对照与版本戳）
2. 绝不热路径拦截（生成永不等待 Jev）
3. 阈值按题型逐一定标，且阶段间不迁移
4. 预登记生死线 → **v2 改为预注册晋升门**（见 §四）
5. 埋点口径预定义：用户选择 = 实际派发的模型（金标准），picker 翻动/节点停留单独记
6. 缓存分层：模型层与渠道层缓存分离，渠道失败转移结果不回写模型层缓存（防缓存「学会」失败）

## 四、评价指标体系（取代 v1 北星「一致率」）

| 角色 | 指标 |
|---|---|
| 主结果 | 单位成功图像成本、生成成功率、regen/edit 率、保留率 |
| 对规则 uplift | Auto-2 vs 手选、Auto-3 vs Auto-2 的 **A/B 结果差**（用户级随机） |
| 校准健康 | 再校准后 ECE、高置信段 decision-curve net benefit |
| 护栏 | Auto 7/30 日留存、高置信建议覆盖率、探索率下限 |
| 诊断（降级） | 分场景 override 率、与手选一致率（按新老用户分层，仅诊断） |

**Jev 存在的唯一区域**：高置信、与用户/规则不一致、但结果更好的决策。一致率把这块当错误——降为诊断。

**预注册晋升门（同时满足才 advisory）**：
(a) 再校准后高置信段对**结果**的净收益 ≥ 规则，预定最小效应量 + 用户聚类 CI 不含 0
(b) 低置信段强制回落且无结果伤害
(c) 固定 n 或 always-valid 界，禁止 peeking
(d) advisory 上线后再做 on-policy A/B，shadow 数据不得直接外推全量

任一失败：**停在 shadow 或回退规则，记录为「表征失败」**（state/候选集/λ 的问题），不是「Jev 死刑」——失败域不可逆过刑。

## 五、偏好反哺（两阶段拆分，取代 v1「从本日启动写回」）

**采集（Phase 2 起）**：服务端落库；元组 = (场景, 候选集, 规则选择, 用户选择, exposure/位置, 版本戳, 网络条件)。埋点实际比 v1 前移——Featured/Auto-1 就开始（手动选择不依赖规则层）。

**闭环（advisory 后 + 结果指标护栏齐备才准）**，最低正则（缺一不许写回第 0 层）：
- 先验 + 最小样本：经验贝叶斯，场景级 n<N0 只用全局策展
- EWMA 半衰期 2-4 周；信任域单日权重移动 ≤ε
- 层次收缩：用户 → 场景 → 全局，稀疏用户拉回全局
- **pairwise（Bradley-Terry）**：X 被换成 Y = Y≻X，不是 Y≻一切
- 探索必配（ε-greedy/Thompson），倾向写入日志，离线评估 IPS/DR
- 两时间尺度：「永不用 X」可快，排序权重必须慢
- 滞回窗口 < 偏好半衰期，仅高置信+高样本量启用

存储：V2 表 schema **现在就定**，V1 localStorage 存序列化后的服务端行结构（迁移=批量上传）；多设备合并语义（LWW vs 场景聚合）随 schema 定。偏好摘要喂 TypeSafe = 行为画像出境第三方，需数据政策口径（非纯工程）。

## 六、Multi / 透明化 / UX 裁决（gemini 裁定采纳）

**Multi**：✦ Auto = picker 单选顶槽位（第 15 个选项）；Multi = 底槽高级特性，激活时 ✦ 置灰（互斥，禁嵌套）。信号语义现在定：{A}→{A,B} 不是对 A 的负投票；一致率在集合上无定义——日志从第一天打 mode 标签。真成本在 N 选 K 的 retry/部分失败语义，不在选中态 UI。

**透明化两级**：日常态一行 chip（「检测到【写实人像】，已匹配 Flux.1」）；探查态 tooltip ≤2 项依据。**严禁直接吐 Jev 原生 reason**——后端映射为产品语义字典（enum）再拼装（防机器味 + 防事后粉饰）。

**改选反馈**：轻改选**绝对沉默**（创作心流不可打扰）；同类场景连续 3 次改选后，在**结果卡片边缘**出微交互横条「是否设为此场景默认偏好？[设为默认][仅本次]」——系统递笔请求授权，不自作主张。

**Featured**：以分组/首屏 Tab 存在，**严禁侵占模型行右轨**（T 结构的操作锚点，防广告位既视感稀释 Pinned 掌控感）。
