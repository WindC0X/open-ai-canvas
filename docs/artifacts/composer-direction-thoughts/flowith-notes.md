# Composer 方向思考 · flowith 对照笔记（2026-09-29）

> **性质声明**：这不是 2.0 规划，是零散思考的存档。三项中只有 **dock 左移** 采纳可能性较大；
> 另两项（composer 集中化、follow-up 引用链）涉及面太广，**只做参考保留**，不排期、不立项。
> 状态：思考稿（用户 2026-09-29 定性）。

## 背景

batch-12 三轮 rider（chip 遮 dock → clamp 让位〔撤回〕→ dock 提层 + 纯贴附恢复）暴露的
结构性事实：**每个节点挂一个 composer pendant 与 dock 全局工具带在同一空间竞争**，
冲突族（遮挡/让位/z 梯级）是架构级的，靠 rider 只能止血。本笔记记录 flowith 的
参照解法与我们的取舍评估。

## 参照物：flowith 的做法（8 图实证，2026-09-29 截图）

### 1. 集中式底部 composer（无每节点挂件）

- 单一底部生成坞：模式胶囊（对话/图像/视频 · 模型选择器）+ 提示词卡 + 参数行
  （回形针 / 比例 / 分辨率 / 风格 / 份数 / 提交），见参考图 1-3。
- 可完全折叠成一根细胶囊输入条，最大化画布视野（图 4）。
- 生成流程 = prompt 节点（`● 我`）→ 虚线 → 结果节点，节点本身无输入 UI（图 5）。

### 2. 选中节点的联动（图 6-8）

- 选中图片节点：紫色发光描边 + 顶部后处理工具栏（裁剪/HD 放大/背景移除/变体/
  重生成/复制/下载/删除）+ 右缘 `[+]` 连线把手 + 底缘 `✨ Follow Up F` 把手。
- 底部 composer 自动回填该节点生成时的风格标签（用户红框标注的参照点）。
- 提交按钮因上下文就绪而点亮。

### 3. Follow Up（F 键）：单链上下文引用

- 点击即引用「节点之上的所有上游（文本）」作为上下文，与 composer 框内内容、
  显式引用一起作用于生成。
- flowith 是单线竖向连线，follow-up 的遍历语义在链上天然收敛。

## 三项取舍评估（用户 2026-09-29 裁定）

| 方向 | flowith 依据 | 我们的取舍 | 定性 |
|---|---|---|---|
| **dock 左移到左侧边栏** | 左轨极简 4 图标条（+/搜索/历史/设置） | **采纳可能性较大**——但与上游新出的侧边栏冲突，需等上游侧栏稳定后再评估；届时可考虑 dock 并入侧栏成为其一节 | 候选（等上游） |
| **取消每节点 composer，集中到一处** | 底部生成坞 + 选中联动 | 涉及面太广，**仅参考保留**：好处是 pendant-vs-dock 冲突族结构性消失、画布密度降低、参数位置恒定；代价是"选中即编辑"直觉丢失、引用管理显式化（chip churn 风险：网状画布下选中常为了移动/框选，非编辑）、参数面板 2.0 与此互为同一张图必须合设计 | 参考保留 |
| **点击即引用 / Follow Up 链式引用** | 选中自动回填风格标签；F 键引用上游全部文本 | 涉及面太广，**仅参考保留**：flowith 的自动引用以单链隐喻为前提；我们网状画布下自动引用会 churn，最多考虑"单选自动/多选不自动"或"一键 affordance"；follow-up 的上游遍历语义（直接上游?文本 only?跨 frame?）需定义，电商管道流（线性）场景下较适用 | 参考保留 |

## 与现存决策的关系

- **rider-2 语义（已定，2026-09-29）**：dock = 全局工具带（`--z-global-tools: 160`），
  挂件纯贴附从其下穿过；挂件 footer 入带 = 出屏语义。本笔记不改变该裁定。
- **参数面板 2.0（已定，2026-09-28）**：侧栏两栏方案（自定义/预设组/存为预设/管理）。
  若未来认真评估 composer 集中化，该方案与集中化互为约束，需合并为一张总设计图。
- **上游观察点**：上游侧边栏形态稳定之时 = dock 左移冲突可正式评估之时。
