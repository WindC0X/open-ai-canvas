## 一、实录要义（按发言人）

**L（真实业务需求方）**——与内部员工+朋友实测后的反馈：
- 「画布虽然高级，但是太复杂，真正给到员工用的，他们就希望这个视频或者图片丢进去，然后就能产生出他们要的效果」
- 「电商好用 = 简洁便捷直接，功能要多样化」
- 「具体的问题具体处理：**抠图就是抠图，换装就是换装，换模特就是换模特，换场景就是换场景，做带货广告就是做带货广告**」
- 「现在我们的 agent 那么强大，改造电商时机已经成熟，**无非是提示词 skill 的问题**」

**黑色饼干.（上游方向派）**：「现在的主要发展方向还是漫剧，电商的感觉不是很适合」→ 上游主线确认在漫剧/短剧。

**会开花的（务实派）**：「众口难调」「自己二开吧」；功能愿望：文本节点可加载 skill（自评「作用不大，写提示词效果一样」）。

**Elio（在做的二开者）**：
- 自有一套电商出图工具，**以插件形式**整合进 fork；正在做「首页出图做成跟 gpt 一样 + 流式对话」
- 场景：装饰画跨境电商（截图含西语文案 Marco de madera）
- 痛点：「gpt 降智给我改成内置提示词了，很垃圾」；判断：「后面的图片模型很简单了，理解能力还是比较强」

## 三、上游分化窗口确认 + 竞争格局修正

- 黑色饼干（上游方向派）明确电商「不适合」→ 上游不会深做，**分化窗口比预想更稳**（与 90 天 feat 零电商词 + 轻渗透口径互证）
- 但需求在社区内**真实存在且正在被散装满足**：Elio 类二开者以插件形式自建——**无人成体系**（无渠道预设/白底规范/批量产线/分层能力栈）
- 战略含义：电商 fork 车道有需求、无系统玩家 = 我们的窗口；做成后具备「社区参考实现」地位，与 C 线机会主义归还策略天然衔接

## 四、设计分叉登记（不跟，但记录）

群友方案：**首页 ChatGPT 式流式对话 / agent 移到首页**（Elio 在做、会开花的提议）。
我们不跟的理由：
1. UX 走查发现 #8：空画布入口已过载（3 主 + 4 快捷 + dock 语义重叠）——再加首页入口恶化
2. 画布 = 产品差异化本体（结果可编辑/多图对比/批量组织），纯对话面给不了
3. Agent 面板新对话态（starter 卡载体）**就是**小白看到的第一个界面，零新增 surface

**但要白嫖试点数据**：Elio 的首页流式对话 = 免费用户试点。若 W5 starter 卡上线后小白反馈仍指向「要更直接的对话入口」，再重评 quick-tool mode。

## 五、降智警示（两段式提示词的脆弱点）

Elio 的「gpt 降智→内置提示词很垃圾」是重要运营信号：两段式（LLM 出 spec→图像模型）依赖 LLM 质量，**低价号池的降智期会伤 spec 生成**。预案：
- F-02 起的电商技法采用 Flora 的 **preset spec 模板化**（预凝缩 900-1500 字 spec 直接入模板，LLM 只做变量填充而非全程生成）——降智期退化为模板+变量，下限可控
- 该预案写入 F-02 任务书输入清单
