## 总判定

分期骨架成立、依赖序正确（渠道现成→规则便宜→Jev 最后→Multi 挂起），「Jev 参与不依赖 + 规则底座常驻」是对 2 周龄厂商零评测生态的正确姿势。但 Auto-3 内部有两处按现文实施必返工的矛盾，Auto-1/2 边界「概念干净、合同不干净」。

## P0

**P0-1　Noul 原语映射与硬约束 #2 自相矛盾（4.2 vs 4.3）**
「兜底触发？」的判定输入（运行时失败、路由耗尽）只存在于派发时刻——放上去就是把生成可靠性耦合给一个发布 2 周、无第三方评测的外部服务。「弹回手动？」是提交后交互动作，同样违反「提交时刻只有缓存命中或跳过」。若挪到预选阶段预判，输入尚不存在，决策无意义。按现文实现，要么破坏零阻塞承诺，要么是死代码。任务书前必须裁决：Noul 仅限「作用于下一次生成/非阻塞 UI」语义，或删除该映射。

**P0-2　4.4 时序设计押注 P-C 未决项**
「节点创建/防抖时预选」隐含粒度=按节点，而 P-C 明确粒度待定（按节点/按次生成）。若裁为按次生成，预选触发点、缓存 key、负投票口径、✦ 展示位全部返工。时序是承重墙。P-C 语义清单（尤其粒度）必须前移到 Auto-1 任务书之前裁决，不能与 Auto-2 并行漂着。

## P1

1. **shadow 度量基建缺三样，生死线在数学上算不出来**：(a) shadow 日志必须服务端落库——localStorage 用户清缓存即样本自删，且无法跨用户聚合，预注册生死线不可执行； 每条日志必须记「规则底座会选什么」+ ruleset 版本 + 偏好版本，否则「对比规则基线」无分母、跨版本聚合是非平稳序列。
2. **北星有复述陷阱**：Jev state 含底座候选 → 高一致率可能只是复读规则。必须分「Jev≠规则」子集报 lift，否则「达标」无意义。
3. **advisory 无守门**：展示建议即引入曝光/锚定偏差，用户接受默认≠独立证据；shadow 期阈值不可迁移到 advisory——这是你们自家 jaggedness 教训的「阶段维度」版，教训被移植得太窄。改二元切换为 canary + 持续 shadow holdout 小流量，补 advisory 回滚线。
4. **能力档案粒度核实**：卡里自己写明 provider 间「支持特性」不同 → capability profile 必须是 (logical_model × provider) 二元组。若现挂模型级，Auto-1 必撞「模型说支持、渠道不支持」。这是 Auto-1 潜在阻塞项，任务书前查清。
5. **Auto-1 把路由表从静态配置变成计算产物**（价低×稳定性动态排序）：需版本化 + 审计（「为什么走这条渠道」要能回答——透明化不能只给 Jev 做）+ 新渠道冷启动先验（无 attempts 数据裸按价格排 → 低价吸量→失败骤降→震荡）。且该打分引擎与 Auto-2 第 0 层同源，Auto-1 就按共享组件建，不要建两次再抽象一次。
6. **预选调用链未定**：触发在客户端，执行按 PROMPT_ENHANCER 骨架应在服务端 → 需新增预选端点（鉴权/限流/prompt 摘要长度上限——防抖高频触发，不设上限成本和延迟都失控）。跳过率要当 SLO 埋：官方 70-500ms 无 p99 口径，超时若设 500ms，跳过率高到 advisory 形同虚设。
7. **偏好存储合同**：V2 表 schema 现在就定、V1 localStorage 存序列化后的服务端行结构，迁移退化为批量上传；多设备合并语义（LWW vs 按场景聚合）现在不定，V2 上线即数据冲突。另：偏好摘要喂 TypeSafe = 行为画像出境给新第三方，需数据政策口径，不是纯工程问题。

## P2

1. 埋点前移：手动选择日志不依赖规则层，应随 Featured/Auto-1 启动——「偏好采集从 Auto-2 起」晚了两卡。
2. Multi 信号语义现在定（便宜）：{A}→{A,B} 不是对 A 的负投票；「一致率」在集合上无定义。实现可挂起，日志从第一天打 mode 标签。
3. Multi 1.5-2 人日低估：真成本在集合的 retry/部分失败语义（N 选 K 挂了重生成谁），不在选中态。
4. 时长徽章按 (model×provider×分辨率桶) 聚合，全局滚动均值必然误导。
5. 新渠道稳定性排名加 Laplace 平滑/最小样本下限。
6. 合批 12.2x/10x 是官方 cookbook 口径，本地实测再进预算；「保留 vs 删除」噪声大（画布整理≠不满），低权重或结合 edit 距离；生死线预注册要带具体数字，不是「达标」二字。

## 专属必答

**1. shadow→advisory 被低估的风险**
- **埋点口径**：「用户选择」未定义——picker 翻动值、节点停留值、还是实际派发值？建议以「实际派发的模型」为金标准，中间态单独记。缺版本戳则一切跨时间聚合无意义。
- **state 组装**：prompt 摘要谁生成？再引一次 LLM 调用 = 预选路径多一个故障域；机械截断 = 喂垃圾。偏好读侧位置（客户端/服务端）未定，直接决定请求合同。
- **缓存一致性**：缓存 key 不含偏好版本 → 用户纠正后仍供旧建议；模型层与渠道层缓存必须分离，渠道失败转移的结果不能回写模型层缓存（否则缓存「学会」失败）。
- **滞回×失败转移**：滞回钉住模型 X 且其路由耗尽时，「换商用模型」这种跨逻辑模型兜底**当前路由表表达不了**（routes 挂在逻辑模型内）——若产品语义需要它，这是卡里不存在的新路由构件。滞回期间的用户「接受」是暴露偏差样本，不是独立证据（详见 P1-3）。

**2. 时序承诺站得住吗**
作为「不阻塞」承诺站得住（跳过路径可实现）；作为产品承诺站不住。破坏场景：
- **防抖窗口内手动切模型** → 迟到预选回写覆盖用户手选。必须「显式手选粘滞 + 覆盖即负投票」——同一个优先级逻辑既是 UX 又是埋点，写错两头一起坏。
- **提交与预选写入竞态** → 提交必须快照决策，迟到预选只作用于下一次生成；否则 picker 显示与实际派发模型不一致。
- **粘贴即提/复制节点/快速连提** → 必跳过，advisory UX「时有时无」非确定；复制节点不能计为「反复手选」信号（污染遥测）。
- **多节点并发**：共享偏好 store 读改写竞态；同 prompt 兄弟节点共享缓存 → 纠正节点 A 后 B 跟不跟随？粒度未定前无答案。
- **retry/regenerate**：应沿用已记录决策走 route_attempts；重试时重新预选换模型 = 把模型质量遥测和 auto 质量遥测搅在一起。
- **弱网**：跳过率飙升，shadow 指标被网络环境偏置——按网络条件分层统计。

**3. Auto-1/2 边界**
概念层面干净，四个藏雷会导致返工：
- **✦ 有两种含义**（模型 picker 里的 auto 条目 vs 模型已选 + 渠道 auto）→ 状态机 (model∈{explicit,AUTO})×(channel∈{explicit,AUTO}) 必须显式枚举。T 行结构马上落地，状态空间现在不定，UI 合同返工；
- 打分引擎同源（P1-5）；
- 能力档案二元组粒度（P1-4）；
- **「用户/场景定模型」在 ✦ 模式下模型槽仍需填充** → Auto-1 已隐含第 0 层规则的最小版（场景映射+能力过滤），等于 Auto-2 的一部分提前到场。接口按 Auto-2 第 0 层设计，别写临时默认值再换。

**4. 存储切换成本 + Multi 最坏冲击**
- 切换的真成本不是迁移是合同：V1 自由格式会反向锁死 V2 schema（对策见 P1-7）。更深一层：shadow 日志与偏好的**服务端化**才是生死线可计算的前提，V1 localStorage 哲学延伸到日志侧就是 Auto-3 转段判据失效。
- Multi 最坏冲击：决策单元从「任务→单模型」变「任务→模型分布」，最强负投票信号语义失效、北星在集合上无定义。若 Multi 解挂晚于数月偏好积累，全部遥测需集合感知 v2、shadow 基线非平稳、生死线作废、Auto-3 统计推倒重来。对策：**现在只定信号语义 + 日志打 mode 标签**（便宜），实现继续挂起。另 dispatch 侧 N 模型×M 渠道×failover 的部分失败语义是 P-E 真实成本大头。

**排期前必办**：裁粒度（P0-2 解药）→ 定 Noul 边界（P0-1）→ 查 capability 档案粒度 → 定日志 schema（含规则基线对照 + 版本戳）。四项都是纸面工作，一天内可清。
