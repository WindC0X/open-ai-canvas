### 一、分级审查发现

#### 【P0 级】设计若照此实施，将导致重大返工或交互事故

1. **时序跳变引发“参数面板闪烁与重置”雪崩**
   * **位置**：`4.4 工程要点`（输入防抖时异步预选）与背景中同栏的`参数面板 2.0`。
   * **理由**：画布中生图模型的参数 Schema 是异构的（Flux 的 steps/guidance、SDXL 的 refiner/clip skip、DALL-E 的画质档位完全不同）。若在用户输入 Prompt 防抖时异步跑 Auto 切换模型，会导致**右侧参数面板随打字实时重构、滑块跳变、用户已调好的私有参数被强行重置或清空**。这是致命的可用性灾难。
   * **结论**：Auto 绝对不能在用户连续编辑 Prompt 的热操作区“自动静默切模型”。模型预决议必须在明确的生命周期卡点生效（如：节点失去焦点、或只展示建议 Badge 而不直接变更底层 Model ID）。

2. **Auto-1 交付物存在“UX 幽灵空心化”**
   * **位置**：`三、项目卡 P-B (Auto-1)` 与 `二、两层路由地基盘点`。
   * **理由**：文档裁定生图是两层决策，Auto-1 仅做“渠道层按价低/稳定路由”。若在 Auto-2（模型匹配）未上线前将 Auto 暴露在 Picker 上，**用户在 UI 上勾选了“✦ Auto”，系统却根本没有“选模型”的能力**——此时 UI 上该怎么呈现选中的模型？是定死一个全局默认模型只换 provider？这完全违背用户对“Auto 帮我挑模型”的心智预期。
   * **结论**：渠道路由（Auto-1）属于无感知的基础设施（Infra），**绝不可单独包装成 Picker 上的“✦ 模式”交付给用户**。把它当作独立用户特性是产品定义上的虚掷。

---

#### 【P1 级】应修但不阻塞排期，但会大幅影响留存与信任

1. **改选信号“单次负投票”导致的偏好过拟合与“信息茧房”**
   * **位置**：`4.5 偏好反哺信号源`（auto 建议 X 用户改选 Y = 最强显式负投票）。
   * **理由**：创作者改选往往是**瞬时探索**（例如“平时画电商，这把想试个二次元”），而非对 X 的永久否定。若将单次改选直接作为强负反馈喂入 state，系统会在下一次相似 Prompt 中立刻拉黑 X，导致系统表现出强烈的“神经质”与过拟合。
   * **纠偏**：改选行为必须引入**时间衰减与频次窗口**（如：同一场景 7 天内连续 3 次改选才构成偏好迁移），不能单次定性。

2. **Featured 与 Pinned 的视觉认知踩踏**
   * **位置**：`P-A Featured 精选区` 与前置依赖变体 T（右轨 pin）。
   * **理由**：Featured 是“官方运营意志”（推新、推低成本模型），Pinned 是“用户个人意志”（我的常用工具）。变体 T 将 pin 锚定在右轨，若在同一空间再引入 Featured，极易演变为广告位既视感，稀释用户对 Pinned 的掌控感。
   * **纠偏**：Featured 应以分类 Tab 或首屏分组存在，**严禁侵占模型行内右轨的操作锚点**。

---

#### 【P2 级】改进建议

1. **时长徽章的“假客观”误导**
   * **位置**：`P-F 时长徽章`（任务日志滚动均值）。
   * **理由**：生成时长 = 渠道排队耗时 + 模型推理耗时。生图受并发拥堵影响极具抖动性。直接打“均值 3.2s”若遇上排队 15s 会造成强烈的被欺骗感。建议降级为“快/中/慢”区间档位或打上“通常 < 5s”。

### 二、分期路线评审与重构

**当前路线不成立。**
现有路线（Featured → Auto-1 → Auto-2 → Auto-3 shadow → advisory）的致命破绽在于：**Auto-1 在产品层是个“不可见的幽灵”**。底层渠道路由本来就已有代码，用户不需要在界面上选“自动选渠道”，用户要的是“自动生好图”。

#### 建议切分重构为：三阶段进化线

```
[Phase 1: 认知与归拢] (当前排期)
  ├─ P-A: Featured 运营策展分组（解决 14 个模型找不着的问题）
  └─ P-B(修正): 渠道路由静默生效（作为全局 Infra 降本，不在 UI 露 ✦ 入口）
         │
[Phase 2: 显式确定性 Auto]
  ├─ P-C: Auto-Core（规则底座）：
  │       输入硬约束（画幅/ControlNet）+ 场景 Preset → 命中规则模型
  │       UI 首次出现【✦ Auto】单选项
  └─ P-C': 埋点建立（记录：规则推荐 vs 用户最终选用，沉淀基线胜率）
         │
[Phase 3: 认知增强 Auto-AI]
  ├─ Auto-3-Shadow: Jev 旁路打分，与 Phase 2 规则跑 A/B 对齐率
  └─ Auto-3-Advisory: Jev 转正，接管高熵 Prompt 意图分流
```

* **更优理由**：Phase 1 彻底剥离渠道层与 UI 的耦合；Phase 2 让用户能感知到一个稳定、可预测的“规则 Auto”；Phase 3 才是 Jev 施展空间，逻辑无缝递进且随时可砍。

### 三、专属必答题

#### 1. “为什么选了它”的透明化程度与 Jev 理由字符串的 UX 风险

* **透明化尺度**：
  * **日常态（轻量化）**：在节点状态栏或参数面板顶部，仅展示一句话 Chips，格式为：`[特性标签] + [模型名]`（例如：“检测到【写实人像】，已匹配 Flux.1”）。
  * **探查态（二级悬停/点击）**：Tooltip 内展示至多两项依据：“① 擅长写实皮肤细节”、“② 符合宽画幅要求”。
* **Jev 理由字符串的 UX 风险**：
  * **风险一：语言失谐**。Jev 是决策分类器，输出易带机器味道（如“High likelihood for photorealistic, cost balance score 0.88”），创作者完全无法理解，造成“技术傲慢”。
  * **风险二：事后合理解释陷阱（Post-hoc Hallucination）**。若 Jev 的权衡主要是因为“该模型当下渠道单价便宜了 $0.002”，但在理由中强行粉饰为“该模型构图更好”，一旦生成翻车，用户会直接对 Auto 丧失根本信任。
* **产品铁律**：**严禁直接将 Jev 的原生 reason 字符串吐给前端！** 后端必须将 Jev 的输出映射为预设的、经过人话润色的“产品语义字典（Enums）”，再拼装给 UI。

#### 2. 改选行为的反馈闭环：沉默学习 vs 显式回应？

* **核心裁决**：**轻改选沉默，模式化改选显式确认，坚决杜绝“爹味”Toast。**
* **信任建立机制**：
  * **单次改选（90% 场景）**：**系统绝对沉默**。创作者在画布上高频试错，任何“好的，记住了”的弹窗/Toast 都是对创作心流的粗暴打扰。
  * **阈值触发显式建议（连改 3 次）**：当系统在同类 Preset/场景下，连续 3 次被用户从 A 改选为 B，在**第 3 次生成完成后的结果卡片边缘**，展示微交互横条：
    > *“近几次同类生成您均选用了 [SDXL Anime]。是否设为此场景的默认偏好？ [设为默认] [仅本次]”*
  * **心理学逻辑**：把“系统自作主张变聪明”变成“系统向创作者递笔请求授权”。掌控权在用户手里，信任才能建立。

#### 3. Auto 与 Multi 的产品表达共存与 Flora 对照反思

* **Flora 形态辨析**：
  * Flora 的 `✦ Auto select model` 是模型下拉框里的**一个枚举项（单选）**；而 `Use multiple models` 是一个**模式 Toggle 开关**。
  * 表面看可以共存，底层逻辑却互斥：用户既然决定用 Multi，心智就是“我要横向对比 A、B、C 的效果”；若用户选 Auto，心智是“我懒得选，系统帮我挑一个最对的”。
* **交互落地设计**：
  * **选择器层级规范**：
    * 下拉列表顶槽位：`✦ Auto 自动匹配`（占单选位）。
    * 下拉列表底槽位：`⚇ 多模型对比生成...`（点击进入 Multi 分裂态）。
  * **互斥逻辑**：
    * 当处于默认单选流：`✦ Auto` 只是 14 个模型之外的第 15 个选项。
    * 一旦用户激活 `Multi`：画布节点派生为多输出槽，**此时 `✦ Auto` 选项必须置灰或隐藏**，禁止出现“在 Multi 模式下勾选一个 Auto”这种嵌套地狱。当前阶段严禁照搬 Flora 的双重开关，Multi 应独立为高级实验特性，避免污染单选主交互。

#### 4. 弹回手动（Noul 门）的 UX 语义与时机

Auto 不该“打肿脸充胖子”，以下三种场景必须触发 Noul 认怂，交还控制权：

1. **能力硬断崖（Capability Collision）**：
   * 用户在节点中加载了 LoRA、ControlNet 姿态图或指定了 1:4 这种极端异形比例，但所有现有模型中**无一能够兼容承载**。此时 Auto 无法在不损坏画质的前提下做决定。
2. **意图熵极大（Extreme Ambiguity）**：
   * Prompt 只有 1-2 个通用词（如“dog”、“beautiful”）且无历史场景标签，Jev 给出的所有模型评分呈扁平分布（Top 1 与 Top 3 置信度差距 < 5%）。此时任何选择都是系统在掷色子。
3. **成本断层越级（Cost Escalation Gate）**：
   * 规则底座认为普通模型均无法满足（如用户要求极致超清长文本渲染），唯一匹配解是极其昂贵的高阶商用渠道（如 Midjourney API 或某大参数旗舰），单次成本高出常规 10 倍以上。

* **UX 表达不是“报错”而是“聚焦推荐”**：
  * **不可行做法**：弹 Alert 报错“无法匹配模型，请手动选择”。
  * **标准做法**：Auto 徽章变为橙色问号 `[? 待确认]`，自动为用户展开选择器面板，面板顶部高亮并锁定 2 个最接近的候选（“推荐以下 2 款，请确认其一”），将原本的自动化平滑降级为“帮用户二选一”。生成按钮在用户点击前保持为“请确认模型”态，零破坏、零报错。
