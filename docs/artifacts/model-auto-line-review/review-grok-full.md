**结论先讲：分期工程上成立，评价科学上不成立。** Auto-2 必须先成为带结果指标的生产基线；Auto-3 的 shadow 只能当研究轨。现在这张卡把「用户改选」当成标签、把 Jev 厂商校准当可迁移概率、把一致率当北星——三条叠在一起，advisory 晋升标准会系统性选错。下面按决策科学/统计视角只报问题。

---

## P0（照此实施会返工或事故）

**1. 把用户选择当黄金标签，全链路没有结果变量。**  
shadow 裁判、负投票、北星、生死线全部是「Jev/规则 vs 用户手选」。用户手选是习惯+默认效应+信息不足，不是最优模型。优化一致率 = 训练一个高保真复读机，和 Auto 要解决的问题（降低决策成本、在质量/成本/时延上不差或更好）正交甚至相反。没有成功/失败、regen/edit、保留/删除、单位成功成本、时延分位数，shadow 数据不可用于晋升。这不是缺指标，是实验对象定义错了。

**2. 厂商「校准概率」直接当置信门，且与自身一致性设计自相矛盾。**  
校准不可跨任务、跨选项基数、跨输入分布迁移。14 路模型选择 ≠ Jev 训练分布。更糟：4.4 写温度 0 + 缓存 + 滞回——温度 0 把分布压成 argmax，校准意义被销毁；缓存让你不再有独立概率样本。用这套「置信分分层」做 shadow→advisory 门槛，会把「模型对自己训练域的自信」误读成「对我们任务的准确率」。

**3. 两层路由的归因错误会污染偏好。**  
用户哲学是渠道层低价池+商用兜底。失败/慢/贵经常是 provider 的事，用户却改的是模型。负投票记在模型上，第 0 层权重和第 1 层 state 会被渠道噪声带偏。14 模型 × 5 渠道，同一逻辑模型多路由，不拆 (model, provider, 能力差) 就做模型层学习，估计量有偏。Auto-1 先上线会让这个问题在 Auto-2 埋点第一天就发生。

**4. 未正则、未探索就闭环「改选→权重」。**  
P-C「从本日启动」、4.1「负投票喂第 0 层权重」是在没有倾向得分、没有探索、没有最小样本、没有衰减的情况下做 on-policy 贪心更新。结果：默认效应自我强化（惯性接受≠偏好）、近期过拟合、振荡（今天压 X 明天全变成 Y）、冷启动锁死策展默认。logged bandit 数据不能当 i.i.d. 分类标签用。

**5. 生死线用错了假设检验对象，且是点估计裸比。**  
「shadow 一致率 < 规则基线 → 整线终结」有三处致命：  
- 用户选择不是真值，Jev 与规则/用户不一致可能是在找更好的模型；  
- 无样本量、无 CI、无预先效应量、持续偷看 dashboard → 第一类错误膨胀（peeking）；  
- 规则基线在 Auto-2 迭代中会动，比较对象非平稳。  
这会杀掉一个结果更好的顾问，或放行一个只会复读的顾问。预登记方向对，判据写错了。

## P1（应修，不阻塞 Auto-1 排期，但阻塞 Auto-2 闭环和 Auto-3 设计定稿）

**6. Choice 原语与可变候选集不兼容。**  
目录会增删模型。K 路 Choice 的校准、历史偏好、滞回在 K 变时全体失效。应改成对模型独立的适配分/胜率（score-then-rank 或 pairwise），Choice 只做有限固定菜单（例如「规则候选 top-k」）。

**7. 把产品效用函数外包给 Jev Score。**  
「价格/稳定性权衡」是产品政策（可调 λ），不是可从 prompt 推断的客观量表。任务适配度可以问模型；λ 不能问。混成一个 Score，参数不可识别，shadow 里你分不清 Jev 是会选模型还是在瞎猜你的成本厌恶。

**8. Choice / Score / Noul 当独立并行题，没有联合一致性约束。**  
三边际可以互相矛盾（Choice=A、A 的 Score 低、Noul 说该回落）。合批省钱不是理由。要么一个联合决策，要么硬约束：Noul 只在 Choice 置信低于**再校准后**的门时启用。

**9. 粒度未定不是产品细节，是抽样单位。**  
按节点 vs 按次生成改变依赖结构：同一节点连打 8 次几乎不独立，当 8 个样本会严重虚高有效 n、让生死线提前触发。必须先定 unit of analysis，用户级聚类标准误，否则任何一致率都不可信。

**10. 展示面偏误未进数据模型。**  
Featured / 右轨 / 默认选中 / 排序位置会主导点击。不记 exposure/position，偏好估计的是「被摆在第一的模型」，不是「更好的模型」。P-A 若先上，后面所有反哺都被 Featured 污染。

**11. V1 localStorage 偏好。**  
用户级碎片、跨设备断裂、重用户单浏览器主导。shadow 要做的是统计验证，样本写前端等于主动选择偏倚。至少从 Auto-2 起事件进后端，localStorage 只做 UX 缓存。

**12. 分层不够。**  
「按题型定标」对，但不够。必须再切：场景、用户新/老、候选集大小、是否 Featured。总体一致率会把「80% 任务用默认便宜模型」的简单题淹没难例。Jev 的价值只可能出现在难例，总体指标看不见。

## P2（改进）

- 时长徽章用滚动均值是错的汇总：时延是混合分布，应用 p50/p95，且按 provider 分层，否则徽章在惩罚模型而非渠道。  
- 「13 问合批」不要为了 cookbook 倍数而堆无关问题，增加的是噪声维和校准负担。  
- Multi 挂起正确：那是集合选择，不是 14-way 分类，统计对象不同，不要用同一套 Choice/一致率。  
- 滞回+偏好学习会锁死早期错误，滞回窗口必须短于偏好半衰期，或只在高置信+高样本量时启用。

## 分期路线是否成立？

**工程切片：成立。** Featured → Auto-1（渠道）→ Auto-2（规则模型）→ Auto-3 shadow → advisory，依赖方向对：渠道路由已在，规则底座必须永远可独立出结果，Jev 不能进热路径。

**更优切分（按决策科学，不是按人日）：**

1. **P-A Featured 与结果埋点并行，埋点不是顺手。** 成功/失败、时延分位、成本、regen/edit、保留删除、exposure。没有这一层，后面所有模型都在盲飞。  
2. **Auto-1 作为内部路由，不要先当用户可感知的「Auto」品牌。** 用户侧一个 Auto，内部层次化：P(model, channel|task)。Auto-1 先吃成本/稳定性红利，同时把 (model, provider) 结果写进同一套遥测。  
3. **Auto-2 才是生产 Auto。** 确定性规则 + **显式产品 λ**（价/质/稳），权重是旋钮不是从改选里学。改选只采集、不闭环。  
4. **Auto-3 从 Auto-2 第一天起 shadow，但禁止喂第 0 层权重。** 晋升看结果 uplift + 再校准后的决策曲线，不看一致率打赢规则。  
5. **advisory 是第三阶段，不是第二阶段。** shadow 证明的是「离线能预测」，advisory 会改变策略分布，必须再做一次 on-policy A/B。shadow 一致率不能外推。

不建议把 Auto-1 / Auto-2 做成两个用户模式；统计和认知都是一个分层决策。人日仍可按卡拆。

## 四个必答

### 1. 校准能迁过来吗？shadow 要怎样才敢用置信分？

**默认不能。** 校准是 (模型, 任务, 输入分布, 选项集) 上的性质。System One 在自己题型上校准，不等于 14 路生图模型选择校准。多类校准比二元难一个数量级；候选集一变，旧可靠性图作废。温度 0 后更没有概率可校准。

Shadow 最低统计设计（预登记，不许边看边改）：

- **记录元组：** (scene, candidate_set, jev_choice, raw_p, 规则choice, 用户choice, 结果向量, user_id, exposure)。raw_p 必须是温度未砸死的分布；若 API 只给 argmax，置信门项目取消。  
- **先再校准，后用门。** 时间切分（禁止随机切，偏好有漂移）：前段拟合 Platt / isotonic（按题型分开），后段画可靠性图、ECE/Brier。用户级 cluster。未再校准的 raw 分只进附录。  
- **「置信可用」的操作定义不是「高分对得更准」**（那只是分辨力），而是：按分箱后，经验频率≈报告概率；且用它做「听从 vs 回落规则」的 **decision curve / net benefit** 优于「永远规则」「永远 Jev」。只有分辨力没有校准，阈值不可移植——这正是你们从 jev-router 学到的 jaggedness。  
- **样本量：** 总体 ECE 至少约 500–1000 次独立决策；要做分箱+分场景，数量级在数千。检验「高置信段优于规则 δ=5pp」，粗算单层对比就要 ~1500 次独立单位（p≈0.6）。节点内多次生成要按节点/用户聚类，有效 n 远小于 log 行数。达不到 n 就延长 shadow，不许降标准。  
- **切分预登记：** Choice / Score / Noul 三套门，禁止迁阈值。Score 还要单独验证它是任务适配而非价格口味。  
- **负结果也要预登记：** 再校准后高分段仍无 uplift → 置信分只当日志，永不进路由。

### 2. 负投票→权重在统计上稳吗？

**不稳。** 这是非平稳、有偏、缺探索的隐式反馈环。

会出的病：

- **默认/惯性偏倚：** Auto 预选 X，不改 ≠ 喜欢 X。当正样本会锁死初值。  
- **近期过拟合与振荡：** 单次 X→Y 就改权重，下周 Y→X 再改回来。尤其生成是随机的，用户把噪声当信号。  
- **重用户支配、冷启动向策展坍缩。** 事件计数 ≠ 用户计数。  
- **探索为 0：** 未见过的模型永远没有正样本，新模型无法进入考虑集。  
- **延迟与错归因：** regen/画幅失败/渠道不稳，记到模型头上。

最低正则（没有就不许写回第 0 层）：

- **先验 + 最小样本：** Dirichlet/经验贝叶斯，场景级 n<N0 只用全局策展，不许个性化。N0 按场景定，不是拍脑袋 5 次。  
- **EWMA，半衰期 2–4 周**（模型迭代周期更短就更短），旧负票衰减。  
- **信任域：** 单日权重移动 ≤ε，防止振荡。  
- **层次收缩：** 用户 → 场景 → 全局，稀疏用户拉回全局。  
- ** pairwise 而非「Y 是唯一正确类」：** X 被换成 Y 是 Y≻X，不是 Y≻一切。Bradley-Terry / ranking，不是 one-hot 分类。  
- **必须有探索：** ε-greedy 或 Thompson，否则估计有偏。倾向写入日志，离线评估用 IPS/DR，不要用朴素一致率。  
- **两时间尺度：** 「这个用户永远不要模型 X」可以快；排序权重必须慢。  
- **Auto-2 阶段只记不写回。** 闭环是 Auto-3 advisory 之后、有结果指标护栏时的事。

### 3. 「建议一致率」的陷阱；换什么。

陷阱：

- **100% = 复读习惯**，Auto 的边际价值为零。  
- **Goodhart：** 优化它会变保守，永远不敢推更便宜/更新/用户不熟但更好的模型——正好反对「低价池跑量」。  
- **默认效应膨胀：** advisory 一开，一致率相对 shadow 上升，那是 UI 强迫，不是模型变准。  
- **简单题稀释：** 默认模型占大多数流量，总体率由简单题决定。  
- **专家用户被当噪声：** 会改选的人往往信息更多，压一致率等于驱逐高判断力用户。  
- **Simpsons：** 总体赢、商用场景/新画幅输。

Auto 的价值应是：**在可接受质量下减少选择成本，并在质量-成本-时延帕累托上不差于手选，对不会选的用户有 uplift。**

建议北星/护栏换成组合，一致率降为诊断指标：

| 角色 | 指标 |
|---|---|
| 主结果 | 单位成功图像成本、生成成功率、regen/edit 率、保留率 |
| 对规则的 uplift | Auto-2 vs 手选、Auto-3 vs Auto-2 的 **A/B 结果差**（用户级随机） |
| 校准健康 | 再校准后 ECE、高置信段的 decision-curve net benefit |
| 护栏 | Auto 7/30 日留存（关了 Auto 就是不信任）、高置信建议的覆盖率、探索率下限 |
| 诊断 | 分场景 override 率、与手选一致率（按用户新老分层） |

「高置信且与用户不一致、但结果更好」是 Jev 值得存在的唯一区域。一致率把这块当错误。

### 4. 「低于规则基线就整线终结」判据的问题。

除 P0 已说的真值错误、裸点估计、peeking、非平稳基线：

- **方向错：** 顾问的假设是「能在规则打平的地方做对难例」。它应该更常与规则不一致。用「更像用户」当生存条件，选出来的是模仿器。  
- **政策漂移：** shadow 的 P(user choice) ≠ advisory 的 P(user choice | suggestion)。用前者杀后者，外推非法。  
- **基线定义含糊：** 规则底座本身在变（策展标签、价格排序、Auto-2 语义未定）。移动靶不能当生死线。  
- **多重检验：** 题型 × 场景 × 分位，任一路失败就杀会假杀；要全过才留会假留。必须预登记单一主终点。  
- **不可逆过刑：** 失败域更可能是 state 表征/候选集/效用 λ，不是「Jev 这个物种不行」。正确动作是 **不准晋升**，不是烧整条线。  
- **应改成的预登记门（同时满足才 advisory）：**  
  (a) 再校准后，高置信段对 **结果** 的净收益 ≥ 规则，预先定的最小效应量 + 用户聚类 CI 不含 0；  
  (b) 低置信段强制回落，且该段无结果伤害；  
  (c) 固定 n 或 always-valid 界，禁止天天看曲线拍板；  
  (d) advisory 再做一次 on-policy A/B，shadow 不得直接全量。  
  任一条失败：停在 shadow 或回退规则，记录为表征失败，而不是「Jev 死刑」。

**一句话给任务书：** Auto-1 可以按工程卡排；Auto-2 只许规则+采集、不许学习闭环；Auto-3 的卡要重写评价：结果变量、再校准、探索与层次贝叶斯、用户级 A/B。现在的北星和生死线会保证你们要么杀掉有用信号，要么上线一个昂贵的习惯复读器。
