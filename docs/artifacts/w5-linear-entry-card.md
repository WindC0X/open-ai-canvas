## 二、★ 本卡必须兑现的两笔债（控制线明令）

### 2.1 债一：`scenePresetId` 显式传递（F-02 过渡态）

**现状**（`scene-execution.ts:34` 原文注释）：
> 场景入口（Agent 面板）与生成执行器（画布页）不在同一组件树，且 Agent 建的草稿节点由后端 patch 创建 —— 前端入口**无法**直接往节点元数据写 `scenePresetId`。故按「「<场景名>」风格的商拍场景图」这一稳定句式反查场景库。
> **W5 直线入口设计卡出稿后，标记应由链路显式传递（元数据字段已预留），本函数届时退化为兜底。**

**本卡兑现**：

```
现状（过渡态）：
  用户点场景卡 → 回填 brief 文本 → Agent 对话 → generate_media
                                                    ↓
                              执行器按「「X」风格的商拍场景图」正则反查 scenePresetId

目标（显式传递）：
  用户点场景卡 → 卡携带 scenePresetId → 直线流程链路显式写入节点 metadata
                                        ↓
                          执行器直接读 metadata.scenePresetId（零反查）
```

**关键设计**：直线流程的**卡本身就是链路起点**（不经 Agent 对话），
因此卡可以在创建节点时**直接写入** `scenePresetId`：

```ts
// 直线流程的卡 → 节点创建（新链路）
const node = await createTaskNode({
    metadata: {
        scenePresetId: card.scenePresetId,   // ★ 显式传递，零反查
        prompt: buildScenePrompt(...),
        ...
    },
});
```

**`detectScenePresetFromPrompt` 的去留**：**保留为兜底**（Agent 路径仍可能走文本），
但**直线流程不再依赖它**。注释同步更新（从「过渡形态」改为「Agent 路径兜底」）。

### 2.2 债二：统一任务面接线（与姊妹卡的接口）

**本卡产出的任务**必须挂到统一任务面（`UnifiedTaskFace`），**不是**新建一个任务 UI。

```tsx
// 直线流程的任务呈现（复用姊妹卡组件）
<UnifiedTaskFace
    taskIds={[task.id]}
    showOpenInCanvas={true}      // ★ 硬验收②「给而不要求」
    onDownload={handleDownload}  // ★ 硬验收③
/>
```

### 3.2 梯度 1：直线流程（受限排布门控）

> TapNow 式受限排布（同画布门控 allowed/locked/hidden），固定步骤以节点呈现；
> 遵守 PRODUCT.md 反参照——不是把画布藏起来的一站式向导，是直线流程跑在画布之上

**落点**：`headless_task` 画布的门控模式。

```ts
/**
 * 直线流程的节点门控（方案 §5 梯度 1）。
 *
 * ★ 反参照纪律：不是「隐藏画布」，而是「画布之上跑直线流程」——
 * 用户点「完整画布」即可解锁全部（毕业机制）。
 */
export type LinearFlowGate = "allowed" | "locked" | "hidden";

export type LinearFlowNodeGate = {
    /** 固定步骤节点：可交互 */
    allowed: string[];
    /** 存在但不可操作（视觉提示「下一步解锁」） */
    locked: string[];
    /** 完全不呈现（未到步骤） */
    hidden: string[];
};
```

### 3.3 梯度 2：话术兜底（零新 UI）

> 画布助手零参数指令直出（LibTV slash 18 场景蓝本）+ uploadHint（Skill Book 蓝本）；
> 零新 UI，挂 skills 话术层附带项

**落点**：**不做 UI**，挂 skills 话术层（后续批）。本卡只**登记**，不实现。

### 3.4 毕业机制

> 引导态露 6 动作（Magnific 6+46 渐进披露），完成首单或点「完整画布」解锁全部，
> node-hover 20 项按 B1 分组呈现

**落点**：
- **触发条件**：① 完成首单（首个任务 succeeded）或 ② 用户点「完整画布」
- **解锁内容**：node-hover 20 项全量 + 画布全部功能
- **B1 分组**：复用 `nodeToolbar.section`（DESIGN.md B1 已定，`tool-definition.ts:190` 字段已有）

**★ 方向性纪律**（方案 §5 原文）：
> 不做独立小白版产品（TapNow 已证明一套代码+门控面够用，**影策方向相反：默认门控关着，主动解锁**）

⇒ **默认门控是「关着」的**（用户看到完整画布），**主动解锁**才进入引导态？
**不，读原文**：「默认门控关着，主动解锁」指的是**影策不做「默认隐藏、被动解锁」**，
而是**默认完整、引导态是可选进入的**。

**★ 精确解读（控制线 2026-10-04 确认，方向钉死）**：

- TapNow 模式：默认引导态（小白看不到全部）→ 毕业才给画布
- **影策模式**：**画布全量在场**（默认完整）→ 用户**主动**进入引导态（如点卡）→
  **门控只锁「直线流程内的装饰项」**

**两条硬依据**：
1. **PRODUCT.md 反参照**：「不把画布藏起来」
2. **硬验收②**：「画布在任一步可达」双条件

⇒ **门控只作用于「直线流程内」**，**不影响常规画布使用**。
（★ 控制线确认：「你的解读正确，照此实现」）

## 四、★ 工具页分层判据（方案 §14，本卡含）

### 4.1 判据原文（DESIGN.md 已落笔）

> 按「**复杂度 × 交互形态**」分配界面层级，同一资产多入口：
> - 高复杂度（多步编排/专属参数面）→ **独立工具页**
> - 中复杂度 → **画布内弹窗/浮层**
> - 低复杂度 → **画布外通用交互页**（预设卡/快捷指令/chips）
> - 零复杂度（纯资产）→ **模板/预设直接套用**

### 4.2 本卡的落点（判据 × 直线入口）

| 复杂度 | 界面层级 | 直线入口的对应 |
|---|---|---|
| 高（多步编排） | 独立工具页 | **不在本卡**（F-12 电商工作室，W8 重估） |
| 中（专属参数） | 画布内弹窗 | 场景图卡 → `CanvasNodeSuperResolveDialog` 类 |
| **低（预设卡）** | **画布外通用交互页** | **★ 本卡主体**（`/create` 卡网格） |
| 零（纯资产） | 模板直接套用 | R25m 收编的 5 源预设（风格/光照/机位/镜头） |

### 4.3 「同一资产多入口」机制

```
一条能力/资产 → 多个入口（按档位生成）
例：场景图能力
  ├─ 档 0：/create 点卡（小白，不见画布）
  ├─ 档 1：直线流程（受限排布）
  ├─ 档 2：画布内弹窗（熟手）
  └─ ⌘K 命令面板（全用户）
```

**★ 与能力组织层的关系**：这正是能力条目（`CapabilityEntry`）的 `tier` 字段的生成规则
（R25m 已落 2 条目，本卡消费）。
