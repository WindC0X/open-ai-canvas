## 三、★ 工程约束（方案 §5 原文 + 教训来源）

### 3.1 隐式容器工程约束（一字不改）

> 隐式画布打 `workspace_type: 'headless_task'` 容器元数据；任务状态流转锚定全局 TaskID、不监听当前画布事件；用户首入画布时流式自动整理排布（防状态反噬与画布污染，pending-test.mdx 撤销反噬教训）

**逐条拆解**：

| 条款 | 含义 | 本卡落点 |
|---|---|---|
| **① `workspace_type: 'headless_task'`** | 小白流程若需要画布承载产物，该画布打这个标记 | §四.2 数据模型 |
| **② 任务状态流转锚定全局 TaskID** | 任务面订阅 `taskId`，**不订阅画布事件** | §四.3 订阅契约 |
| **③ 不监听当前画布事件** | 画布撤销/编辑/同步**不得**影响任务面状态 | §四.4 反模式清单 |
| **④ 用户首入画布时流式自动整理排布** | 首次打开 headless 画布时，节点自动排布（防乱） | §四.5 首次呈现 |

### 3.2 ★ 教训来源（约束的存在理由，必须带上）

**`docs/plans/pending-test.mdx:3763` 撤销反噬实测**：

> **撤销反噬**——撤销只改云端，本地 IndexedDB/水位残留被 S08「仅本地领先」路径推回云端（**实测撤销 95 秒后被自动同步反噬**）→ 成功路径 discardLocalCanvasProject + refresh 后强制 drain

**同族前科**（同在 `pending-test.mdx`）：

| 位置 | 现象 |
|---|---|
| `:3843` | 「多标签页撤销反噬」「adopt 失败后基线分叉无防反噬」 |
| `:3851` | 「flush→POST→adopt 在途窗口：本地编辑被 adopt 静默丢弃 / adopt 失败后基线分叉触发反噬」 |

**⇒ 约束③「不监听当前画布事件」防的正是这个失效模式**：
画布事件驱动的同步会在用户不期望时**反向覆盖任务态**（撤销反噬的本质 = 状态被非预期路径改写）。

**★ 本卡的额外价值**：把这条约束从「防止画布污染任务」扩展为**双向**：
- 任务面**不监听**画布事件（防画布污染任务）
- headless 画布的**自动整理**不触发任务重跑（防任务污染画布）

## 四、架构设计

### 4.1 组件分层（三档共用同一任务面）

```
┌─────────────────────────────────────────────────────────────┐
│  统一任务面组件（UnifiedTaskFace）                            │
│  进度 / 阶段 / 状态 / 结果预览 / 下载 / 取消                  │
│  ★ 零画布依赖（不 import 任何 canvas 状态）                    │
└────────────────┬────────────────────────────────────────────┘
                 │ 挂载点（三档）
    ┌────────────┼────────────┬──────────────────┐
    ▼            ▼            ▼                  ▼
┌────────┐  ┌────────┐  ┌──────────┐  ┌─────────────────┐
│ 档 0   │  │ 档 1   │  │ 画布内   │  │ 独立任务中心页   │
│ 点卡   │  │ 直线   │  │ 浮层面板 │  │ /tasks（未来）   │
│ /create│  │ 流程   │  │（F-02）  │  │                  │
└────────┘  └────────┘  └──────────┘  └─────────────────┘
   headless     headless     普通画布      无画布
```

**★ 关键设计**：**同一组件、四个挂载点**。任务面本身**不知道**自己在哪挂载
（通过 props 注入能力开关，如 `showOpenInCanvas`）。

**★ 第四挂载点（`/tasks`）的性质（控制线微调 2026-10-04）**：
它是**条件触发项，不是独立排期项** ——
**能力条目 ≥24 触发工具目录页时一并评估**（与架构方案 §7.4 目录页触发条件同源）。
**不单独立项。**

### 4.2 数据模型：`workspace_type`

**新增字段**（画布容器元数据）：

```ts
// web/src/types/canvas.ts（CanvasProjectMeta 或等价位置）
export type CanvasWorkspaceType = "standard" | "headless_task";

export type CanvasWorkspaceMeta = {
    /**
     * 画布容器的类型标记。
     *
     * - `standard`：用户在画布页显式创建/打开的常规画布（默认）
     * - `headless_task`：小白直线流程隐式创建的容器 —— 用户**未主动进入画布**，
     *   画布只是产物的承载方式。★ 方案 §5 工程约束（2026-10-03 三模型审查采纳）
     *
     * 行为差异：
     * - headless_task 画布：用户首入时流式自动整理排布；不主动出现在画布列表顶层
     * - 任务状态流转**不**受该画布的编辑/撤销/同步事件影响（锚定 TaskID）
     */
    workspaceType?: CanvasWorkspaceType;
};
```

**默认值纪律**：`undefined` 视为 `standard`（**不破坏既有画布**，零迁移）。

### 4.3 订阅契约（锚定 TaskID，不监听画布事件）

**现状核实**：`subscribeGenerationTasks(ids: readonly string[], listener)` —— **已按 TaskID 订阅** ✅

**本卡要做的**：**把事实写成纪律**（防未来改动引入画布事件监听）：

```ts
/**
 * ★ 任务面订阅契约（方案 §5 工程约束，不可违反）
 *
 * 1. 任务状态**只**来自 `subscribeGenerationTasks(taskIds)` —— 服务端推送
 * 2. **禁止**从画布状态（nodes / edges / metadata）推导任务状态
 * 3. **禁止**订阅画布事件（撤销/同步/编辑）来刷新任务面
 *
 * 教训来源：pending-test.mdx:3763「撤销反噬」（撤销 95 秒后被自动同步反噬）
 */
```

**可机检的护栏**（建议）：守卫测试断言任务面组件**不 import** 画布 store：

```ts
// web/test/task-face-independence.test.ts（新增）
expect(taskFaceSource).not.toContain("use-canvas-store");
expect(taskFaceSource).not.toContain("canvas-event");
expect(taskFaceSource).toContain("subscribeGenerationTasks");
```

### 4.4 反模式清单（本卡明确禁止）

| # | 反模式 | 为什么禁止 | 教训来源 |
|---|---|---|---|
| **A1** | 从画布节点状态推导任务状态 | 画布编辑会误导任务面（如撤销后任务面显示回退） | 撤销反噬 |
| **A2** | 订阅画布事件刷新任务面 | 画布事件频率高、语义不同，会引入非预期状态改写 | 撤销反噬 + adopt 分叉 |
| **A3** | headless 画布出现在主画布列表 | 小白不需要看见画布（双条件①） | §5 双条件 |
| **A4** | 任务面 import 画布 store | 破坏「独立可用」（硬验收②） | §5 硬验收② |
| **A5** | headless 画布自动整理触发任务重跑 | 反向污染（任务被画布事件驱动） | §5 约束③扩展 |

### 4.5 首次呈现（流式自动整理排布）

**方案原文**：「用户首入画布时流式自动整理排布」

**设计**：
1. headless 画布**首次被用户打开**时（检测 `workspaceType === "headless_task"` + 首次访问标记）
2. 触发**流式**自动整理（不是一次性 layout，而是**逐节点入场 + 排布**）
3. 整理**不写回任务状态**（只改节点坐标）

**复用**：既有自动整理能力（`canvas-layout.ts`，MASTER-PLAN 提到「画布自动整理四库对比」已有实现）。

## 五、组件契约（统一任务面）

### 5.1 Props（能力注入式，不感知挂载点）

```ts
export type UnifiedTaskFaceProps = {
    /** 任务 id 列表（★ 唯一状态源，锚定 TaskID） */
    taskIds: readonly string[];
    /**
     * 是否显示「在画布中打开」入口。
     * ★ 硬验收②：「给而不要求」—— 默认 true，小白流程可传 false。
     */
    showOpenInCanvas?: boolean;
    /** 点击「在画布中打开」的回调（由调用方决定跳转方式） */
    onOpenInCanvas?: (task: GenerationTask) => void;
    /** 取消任务回调 */
    onCancelTask?: (task: GenerationTask) => void;
    /** 交付步：下载回调（★ 硬验收③） */
    onDownload?: (task: GenerationTask) => void;
};
```

### 5.2 四要素（硬验收②：进度/结果/预览/下载齐备）

| 要素 | 现状 | 本卡 |
|---|---|---|
| **进度** | ✅ 进度条 + 百分比 + 阶段标签 | 复用 |
| **结果** | ✅ `GenerationTaskOutput`（含 `resultState` 六态） | 复用 |
| **预览** | ⚠️ 画布内有；独立挂载点缺 | **新增**（复用媒体渲染组件） |
| **下载** | ⚠️ 画布内有；任务面缺 | **新增**（`onDownload` 契约） |

### 5.3 交付步（硬验收③）

```
任务完成 → 结果预览 → [下载] ← ★ 必须存在
                    → [在画布中打开] ← 给而不要求
```

**纪律**：下载必须是**合规成品**（不是中间产物）。对图片/视频：
- 图片：原始分辨率（非缩略图）
- 视频：完整文件
