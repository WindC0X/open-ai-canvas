## ③ ★ 我补充：V10-g 有一个**灰色地带**需要界定

**问题**：什么算「他人活动工作区」？
```
情形 A：A线 的主仓（正在改，工作区 5 项未提交）⇒ 显然不可读 ✓
情形 B：A线 的主仓【已 STOP 但未提交】⇒ 可读吗？
情形 C：A线 的【已提交 commit】⇒ 可读 ✓（最稳）
情形 D：我【自己的隔离树】（即使应用了 A线 的 WIP）⇒ 可读吗？
```

**★ 我的界定建议**：
```
【可读判据】按「内容是否会变化」而非「谁的工作区」

情形 A（活动）    ⇒ ✗ 不可读（内容实时变）
情形 B（STOP 未提交）⇒ △ 可读，但【必须 md5 对照】（STOP 只是当下静止，随时可能再动）
情形 C（commit）  ⇒ ✓ 可读（内容固定）
情形 D（我自己的树 + 他方 WIP）
                  ⇒ ✓ 可读【但结论只能作预演】
                     因为：内容在我树里已固定，但【它对应的主仓状态可能已变】
                     ⇒ 结论必须标注「基于 md5 <X> 的 WIP」

⇒ ★ 核心判据：**内容是否可能在他处被改变**
   · 若可能 ⇒ 必须锁版本（md5 / commit）
   · 若不可能（已提交 commit）⇒ 自由读
```

**★ 这解释了我预演的性质**：
```
我的树 = 情形 D ⇒ 内容固定（我的树里不会变）
但【结论的有效性】取决于「A线 是否还会改同一份代码」
⇒ 所以预演结论标注 md5 + 声明「不作最终裁定」= 正确处理 ✓
```
