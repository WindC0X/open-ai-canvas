## ② ★ 但我发现一个**共性盲区**：`git checkout` 不清 untracked

**你的操作④→⑤**：

**★ 若 A线 的修复含【新增文件】（如新测试），`git checkout` 不会删除它** ——
因为 `git checkout -- <path>` 只还原 **tracked** 文件的**内容**，不处理 untracked。

**我实测确认（在我自己的树上）**：
```
我的探针残留检查：
  find _f09fix -name "zz-*" ⇒ 零
⇒ 因为我在每轮探针后【手动 rm】
⇒ 但若我忘了 rm，git checkout 不会清理它
```

**★ 这构成一条纪律**（建议登记）：
```
### ★ 隔离树还原的完整步骤（git checkout 不够）

git checkout -- <path> 只能还原【tracked 文件的内容】，不能：
  · 删除 untracked 文件（探针 / 新增测试）
  · 恢复被删除的 tracked 文件（需 git checkout -- . 或 git restore）
  · 清理 .orig/.bak 备份

【完整还原步骤】
  ① git status --short --untracked-files=all  ← 看全部（含 untracked）
  ② git checkout -- .                           ← 还原 tracked 内容
  ③ 手动 rm untracked 残留（或 git clean -n 先预览，再 -f）
  ④ git status --short --untracked-files=all   ← 复确认

【验证方法（我用的）】
  for f in <关键文件列表>; do
    [ -z "$(git diff --stat HEAD -- $f)" ] && echo "✓ $f" || echo "★ $f 有差异"
  done
  ⇒ ★ 逐文件核验比 git status 更精确（git status 可能被 .gitignore 隐藏）
```

**★ 你的还原是正确的**（我实测零残留），但**步骤可以更完备** ——
特别是「同步 A线 修复」这一步，若它含新增文件，`git checkout` 会漏。
