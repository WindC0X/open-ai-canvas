### 1.1 既有缺陷（修复前就存在）

```
productImageCount 写死为 1（canvas-clone-template.ts:105）
  + 空槽位节点被上游解析【跳过】（无 content ⇒ 不是资源节点）

     ⇒ 上游 = [版式图]
     ⇒ 后端按位置编号「图1 = 产品图」⇒ 实际图1 = 版式图
     ⇒ ★ 静默错位（不报错）
```

**★ 我实测确认**：
```
上游资源节点: ["slot-layout"]     ← 空槽位被跳过
productImageCount: 1
⇒ 图1 = slot-layout（版式参考图）被当成产品图
```

### 1.2 ★ 修复引入的新可达路径

**★ 关键差异**：

## ③ 一个语义观察（供 A线 参考）

**`resolveTemplateImageSlots` 的两处处理【不一致】**：

| 场景 | 首位源类型 | 处理 | 结果 |
|---|---|---|---|
| `[文本, 图A, 图B]` | 非图片 | **过滤压缩**（图A 顶到 slot[0]） | ✓ 产品图 = 图A |
| `[空图X, 图B]` | 图片但空 | **保持空**（图B 不顶到 slot[0]） | 产品图槽位空 |

**★ 两者都是【正确的】设计**（A线 的注释论证充分）：
```
· 过滤非图片：因为文本节点【不是图片输入】，不该占图片槽位
· 空图不压缩：因为压缩会让版式图【静默升为产品图】（错位）
```

**⇒ 但组合起来产生一个边界**：
```
[文本, 空图X, 图B]
  ① 过滤 ⇒ [空图X, 图B]（文本被去掉）
  ② slot[0] ← 空图X ⇒ 不填（保持空）
     slot[1] ← 图B   ⇒ 填
  ⇒ 产品图槽位空，版式槽位 = 图B
```

**★ 与「[空图X, 图B]」（无文本）结果相同** ✓ —— 逻辑一致，无矛盾。
**只是这个结果本身会触发 §1.2 的错位路径。**
