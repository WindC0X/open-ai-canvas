## §2 批1：`selfCheck` 污染修复 —— ✅ 正确

### 2.1 缺口确认（控制线的复现 + 我的独立核实）

**缺口**：`selfCheck()` 注入自检消息后**只删 DOM 节点**，但该消息**已进 `msgLog`** ——
记录含目标关键词 ⇒ 后续「`msgLog` 不含目标文案」的阴性断言**必然失败**。

**控制线的两顺序对照**（我核实其代码逻辑）：
```
顺序1 reset→selfCheck→触发→dump: msgLog 残留自检消息 → 阴性断言 = false ✗
顺序2 reset→selfCheck→reset→触发→dump: msgLog 干净 → 阴性断言 = true ✓
```
**⇒ 缺口成立** ✓

**★ 反讽结构**（控制线指出，我认可）：`selfCheck` 是为**让阴性结论可信**而造的，
却**污染了它要保护的证据** —— 与坑3（观测手段改变被观测对象）**同族**。

### 2.2 修复实现（双重）

**修法2（治本）**：
```js
var selfIdx = msgLog.indexOf(SELF_CHECK_TEXT.slice(0, 200));
if (selfIdx !== -1) msgLog.splice(selfIdx, 1);
```
**修法1（显式教育）**：用法说明插入 **2.5 步「自检后必须 reset()」**（含不 reset 的后果说明）

**⇒ 双管齐下**：治本（自动清理）+ 显式（用户显式 reset 更稳妥，且能清历史记录）✓

### 2.3 我的证伪验证

```
基线：11 pass / 0 fail / 27 expect
★ 注入：移除修法2（msgLog.splice）
结果：★ 2 fail
  (fail) 自检注入的假消息被清理（DOM 节点 + msgLog 记录，双重不污染）
  (fail) ★ 证伪：自检记录若不清除 ⇒ 阴性断言必然失败（修法2 的必要性）
```
**⇒ 与控制线声明完全一致** ✓

### 2.4 ★ 边界核实（控制线提到一项，我补测两项）

| 边界 | 场景 | 实测 |
|---|---|---|
| **控制线验证的** | 观察器失效（`ok=false`）⇒ `msgLog` 本无该条 ⇒ `indexOf=-1` ⇒ 不误删 | ✅ 我复现确认 |
| **我补测的边界1** | 观察器失效 + `msgLog` 有**真实历史记录** ⇒ 真实记录**未被误删** | ✅ `msgLog` 剩 1 条真实记录 |
| **我补测的边界2** | 观察器正常 + 有真实历史记录 ⇒ **只删自检那条**，真实记录保留 | ✅ 剩 1 条真实记录 |
| **我补测的边界3** | 真实消息**含**自检文案作子串（但不相等）⇒ **不误删** | ✅ 真实消息保留 |

**⇒ `indexOf` 是「数组元素精确匹配」**（非子串匹配）⇒ 只删**完全等于**自检文案的那条 ✓

### 2.5 ★ 我发现的边界歧义（P3 候选，最终判定为不可达）

**理论歧义**：若真实消息**逐字等于** `SELF_CHECK_TEXT`，`indexOf` 返回**第一个**匹配 ⇒
可能删掉**真实**那条（留下自检那条）。

**我的实测**：
```
★ 自检前: ["未找到要接续的会话（探针自检，可忽略）"]   ← 假设的真实消息
★ 自检后: ["未找到要接续的会话（探针自检，可忽略）"]   ← 剩 1 条（是自检那条）
```

**可达性判定**：**不可达** —— 因为自检文案含**「（探针自检，可忽略）」**这一明确标记，
真实的产品警告**不可能**逐字等于它（产品文案是 `project.tsx:682` 的
`"未找到要接续的会话，请从首页重新进入。"`，与自检文案不同）。
**⇒ 不构成缺陷**，但**记录为已知边界**（若未来改自检文案去掉标记，需重新评估）。
