## A. 从 codex(zcode) 会话提取的经验

**背景**：zcode（codex 系）在 open-ai-canvas-native 用 30 小时主线（1102 条消息 + 4 子代理）做 og-canvas 的 flora 化，失败。本会话开题的第一个任务就是完整阅读这批会话并吸取经验。

### A1. 失败定性（七条诊断的总纲）

**"契约缺陷而非扫描不足"**——og-canvas 死因不是资料扫得不够多（语料其实很厚：381 文件 atlas + 114 线上 chunk + 实拍），而是没有契约就动工：归属面未定、动效规格未立、负面约束未签发，实现期只能反复返工。标志性物证：`node-90-emptyImageBlock-blank.md` 语料只是交互标签堆，没有任何生成中舞台的视觉解剖——"扫描资料理不清"是实指。

### A2. 八条总原则（血泪写成，任何阶段不得违反）

1. **语法改编，不是克隆**——flora 是交互语法参照，不是皮肤/代码来源
2. **契约先行**——没有归属面决策就没有代码；归属面空白=停下来先决策
3. **全局放松、切片收紧**——不要求整体扫描完成；每个切片动工前该切片证据包必须齐
4. **看不见的靠驱动与解码，不靠猜测**——互斥状态用 CDP 驱动采集，内部逻辑用 bundle 解码；都拿不到的标"自行设计，无 flora 参照"
5. **决策影响是唯一进度度量**——新证据不再改变契约决策就停；禁止覆盖率百分比汇报
6. **契约压过工具默认值**——flora 常量覆盖 skill 默认，冲突时登记"有意覆盖"
7. **单线程小切片，禁止空壳铺开**——一次一个节点族，带验收，跑通再铺开
8. **画布层分叉，其余层持续合并**——canvas UI 分叉；backend/services/provider 定期 rebase

### A3. 三层证据模型（知与不知的边界）

| 层 | 回答什么 | 手段 | 边界 |
|---|---|---|---|
| 实机采集 | 用户看到什么 | CDP 驱动 + T1-T12 清单 + tmwd-bridge | 凭据门控行为受账号额度限制 |
| bundle 解码 | 客户端为什么这样 | website-rebuild-skill 逆向 | Turbopack 形态风险 |
| 服务端内部 | 队列/路由/计费 | 无 | **不可知 → 影策自行设计** |

**权威顺序**（06-corpus-index 确立）：实拍截图/CDP JSON > atlas 文档 > 早期笔记。

### A4. 教训对应表（出错先查）

- 发明"呼吸光/扫光/全幅骨架"→ 违反"先查语料"——生成视觉以 phase43 + 动效速查为准
- "Another debugger" 争用 → tmwd 扩展自我竞争 → 已加串行锁
- 服务"死了" → 先跑 `tools/preflight-dev.sh` 再重启（后端 wsl 附着 / vite bun）

### A5. 治理与资产

## B. 本会话自身重复犯的错（37 条用户纠正 → 7 个模式）

### B1. 大语料阅读不完整（3 次，会话开题即中招）

- 05:39 用户截图打脸"这才是最后的对话，反推出你阅读不完整"（漏读 zcode 会话最后两轮，把结局性质判错）
- "zcode 未处理好的你没看到？" / "是不是可以反推到全局：整理、扫描依旧不完全？"
- **解法（有效，被后续沿用）**：workflow 分段全读（17 代理 + 用户消息逐字清单一条不落）→ FINAL.md；本会话崩溃后同样用 workflow 切片法验尸
- 教训：**单次顺序阅读大语料必漏；主会话直读只配当侦察，全量结论必须走分段并行+完整性审查**

### B2. 环境/实例混淆（3 次，最严重一次引发用户爆发）

- "一个是本地影策，一个云端部署的，这都分不清吗？"（09-05）
- 标签显示 localhost 就认不出是本地实例（09-05）
- 09-09 03:26 大爆发："让你到本地的进行校验，不是让你跑去看云端""修了五六回修不好问题还隔着管东管西"
- 教训：**多实例（本地 dev / 云端部署）场景下，操作前必须先显式声明目标实例及其指纹（内网 IP/端口/进程），并让用户确认**；调试会话开的标签≠开发对象

### B3. 凭截图目测 vs 语料权威（翻转门，最典型的重复犯）

- 09-08 08:35："flora 整理的资料你是完全不认是吗？"——上轮凭截图断言"flora 是实心不透明"去掉了玻璃感，实际 flora 是玻璃的，引发整轮返工

- 09-07 21:06："flora 资料都有，不行也可以现场核对 flora，你都看到哪了一直弄不对？"
- 教训：**语料权威顺序（CDP JSON/DOM/CSS computed > 截图目测）必须落成硬规则：每次视觉对齐先引语料条目编号，再动手；截图只用于发现差异，不用于定义权威值**（09-07 20:56 pending-test 已按此立规矩：P51-030 取 computed）

### B4. 验收只管局部、不管整体（验收债）

- 09-08 11:01："为什么你刚刚验收没看到问题，你验收只管局部修正？不管整体是否因此出错、整体是否是向前的？"

### B5. 探针/工具失真当证据

- b449f84 轮自记 CDP 合成事件探针失真，却在失真证据上宣布闭环——"修好了→用户说没修好"循环的直接机制

### B6. 能力短板不主动换工具（全部由用户逼出来）

### B7. 记忆层漂移导致跑偏（会话致死根因）

- 教训：**压缩摘要不能作为事实来源；跨压缩的关键结论必须落盘（文件/git/任务工件）；反射记忆层无上限回灌会撑爆摘要并稀释真实状态**（→ pi 配置层待决：reflections 上限或关闭）

## C. 元教训（两代连读才看得见的东西）

1. **og-canvas 死于"契约缺陷"，本会话在执行层重复了同类错**：八条总原则 09-04 就写进了 00-MASTER-PLAN，但模型列表战役里 B3/B4/B5 全是"契约先行/先查语料/验证纪律"的违反——**纪律写在文件里不等于被执行**。
2. **有效对抗不是"记得"，是硬闸门**：真正止住循环的是把纪律变成不可绕过的形式——P51-030 权威值表（先查语料）、tmwd 真机验收（探针失真）、handoff.md 禁重试清单（本会话死后落地）。新会话延续此法：纪律进清单+钩子，不进记忆。
3. **"资料理不清"是两代共同的死因形态**：og 死于语料文件本身是标签堆；本会话死于记忆层变成 1703 条反射堆。**语料和记忆一样，无结构的积累=负资产**。
