# F-06 扩图模型档位门控（白名单硬过滤）

## Goal

扩图模型槽不再按「支持图生图（maxImages>=1）」放开，改为**档位白名单硬过滤**：模型按扩图适用度分档（推荐/可用/未认证），只有推荐、可用两档出现在扩图工具；档位随渠道模型能力配置维护、渠道编辑器可控；首批只认证 nano 族（本轮实测：主体保持 2–8%、扩展区最干净）。依据：09-20 用户裁定 B1–B4（模型三档白名单）+ 09-28 四问裁定（白名单硬过滤 / 渠道能力配置 / 仅 nano 推荐 / 只做画布槽）。

## Requirements

- R1 档位字段：渠道模型图片能力配置新增 `outpaintTier: recommended | capable | uncertified`（缺省=未认证）。渠道管理「模型能力编辑器」（引用与限制区）提供「扩图档位」控件，可改、随渠道保存。
- R2 默认播种：nano 族（nano-banana-2 / nano-banana2 / gemini-3.1-flash-image）缺省自动标「推荐」；其余模型缺省保持未认证（2.5/sunburst 按用户裁定不升档，等样本集验收）。
- R3 白名单硬过滤：扩图参数条模型槽只列「推荐+可用」档；未认证不出现；打开时若当前模型不在白名单，自动改选（节点原模型 → 配置默认 → 白名单首个）；无任何白名单模型时执行禁用并明示「当前没有支持扩图的模型」。
- R4 提交链兜底：扩图执行 hook 二次校验档位，未认证直接拒绝提交（UI 防线之外的真防线）。
- R5 后端零任务层改动：只扩展能力配置结构/归一/校验，不在任务校验层拒绝（Agent/API 场景本期不限制）。
- R6 测试与文档：Go 单测（播种/保留/非法值）+ 前端单测（谓词/播种）；features / pending-test 文档同步。

## Acceptance Criteria

- [ ] AC1：渠道管理图片模型编辑器可见「扩图档位」（未认证/可用/推荐），保存后 capability_config_json 含新字段且往返不丢（Go normalize 保真）。
- [ ] AC2：默认播种生效——nano 族模型缺省=推荐；gpt-image-2.5/sunburst 缺省=未认证。
- [ ] AC3：扩图槽只列白名单模型；测试环境实测只显示 nano-banana-2，2.5/sunburst 不出现；当前模型不在白名单时自动改选。
- [ ] AC4：白名单为空时执行禁用 + 「当前没有支持扩图的模型」文案。
- [ ] AC5：hook 兜底拒绝未认证模型提交。
- [ ] AC6：go test（app 包）+ bun test（新增用例过、存量基线不回退）+ tsc 通过；接口级证据留档。
- [ ] AC7：任务卡 + 文档同步；工作区 hb、分支 feat/ecom-f06-hardblend；无新增依赖、不改 globals.css。
